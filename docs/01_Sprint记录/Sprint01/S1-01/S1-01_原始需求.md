# S1-01 原始需求

## 登记信息

- 类型：OPT
- 标题：压缩能力 seam：原生压缩优先，前缀命中兜底；触发取 95% 与模型限额先到者
- 优先级：P0
- 估算：8 点
- 依赖：无
- 来源：Runtime request binding `pi:/profile/docs/01_Sprint记录/Sprint01/WF-S1-04_压缩能力seam与前缀命中_方案决策.md#approved-2026-11-01`


## 原子结果

压缩请求复用上一次请求的前缀以命中 provider 前缀缓存；不支持原生压缩的 provider 走前缀路径；触发点按 95% 与模型限额取先到者

## 验收标准

1. 连续两次压缩，第二次请求的消息数组是第一次的前缀
2. 摘要请求不含独立 summarizer system prompt，也不含序列化历史文本
3. 摘要请求参数与直接对话一致，不新增 max_tokens 或 reasoning 覆盖
4. 触发点等于 min(contextWindow × 0.95, contextWindow − maxTokens)，32K 与 1M 窗口比例语义一致
5. 声明原生压缩但未实现时返回 unsupported，不静默降级到全价请求
6. 无上次请求或前缀已失效时抛 PrefixUnavailable 并走冷启动序列化分支
7. 同前缀对照下 provider 缓存命中比例不低于 90%

## 工程硬性验收条件

1. 【G1】设计与实现必须符合 `$codebase-design`，以 Module、Interface、owner、依赖方向和测试面证据验收。
2. 【G2】Skill/Runtime 改造必须符合 `$deterministic-skill-refactor`；普通程序架构重构必须符合 `$program-architecture-refactor`，按 Rust → TypeScript → Python 顺序评估目标语言并记录迁移状态。
3. 【G3】架构重构必须迁移旧测试的行为保障至新 Interface，建立旧测试→行为→新测试映射；新测试通过后才删除被替代旧测试，无旧测试时先补行为基线。
